# Config ownership

Keep model, data, pretraining, mid-training, RL, reward, curriculum, and evaluation settings in the matching directories. Add a runnable config only with its entry point. Every expensive run must save the full resolved config and seed under `artifacts/<run-id>/`.

[data/leandojo_nat_v1.json](data/leandojo_nat_v1.json) runs with [scripts/data/prepare_leandojo.py](../scripts/data/prepare_leandojo.py). It pins the public archive, source revision, toolchain, file selection, exclusions, duplicate threshold, and candidate caps. The runner saves the resolved config in its audit report. See the [data preparation command](../docs/results/01_data_preparation.md#data-preparation).

[data/leandojo_number_theory_v2.json](data/leandojo_number_theory_v2.json) uses the same runner for the broader candidate pool on cpu-angad. It includes prerequisites and number theory beyond the Nat probe. It preserves official random split memberships. Family labels come from source files; difficulty and pedagogical prerequisites remain unmeasured. See [the remote data section](../docs/results/01_data_preparation.md#broader-candidate-pool-on-cpu-angad).

[eval/qwen_05b_probe.json](eval/qwen_05b_probe.json) runs with [scripts/eval/probe_qwen.py](../scripts/eval/probe_qwen.py). It pins the base checkpoint, public data revisions, selection seed, prompt and generation caps, and the formal validation manifest. [midtrain/qwen_05b_gsm8k_lora.yaml](midtrain/qwen_05b_gsm8k_lora.yaml) uses the upstream MLX-LM LoRA trainer for the supervised diagnostic. See [the capability probe](../docs/results/02_qwen_capability_probe.md#qwen-capability-probe). Lean and formal-training configs remain pending.

[rl/qwen_05b_whole_proof_grpo.json](rl/qwen_05b_whole_proof_grpo.json) runs with [scripts/train/run_grpo_pilot.py](../scripts/train/run_grpo_pilot.py). It defines the separately authorized whole-proof pilot using TRL GRPO. Random and curriculum arms share theorem occurrences, initial weights, and terminal reward. Interactive training remains a separate unimplemented comparison. The runner supports `--dry-run` with explicit prepared data, checker, environment, and output paths.

[rl/qwen_05b_prerequisite_grpo.json](rl/qwen_05b_prerequisite_grpo.json) uses the same runner with tasks from [the prerequisite preparer](../scripts/data/prepare_prerequisite_curriculum.py). Random and prerequisite orders share a decreasing assistance schedule and fixed premises. Training readiness uses training tasks. Final evaluation uses no task-specific assistance. The current total budget ceiling includes prior rentals; the launch ledger supplies cumulative reservations.

[rl/qwen_05b_prerequisite_grpo_syntax.json](rl/qwen_05b_prerequisite_grpo_syntax.json) registers the syntax-assisted retry. Full assistance includes generic Lean 4 forms with placeholders. Readiness samples this changed prompt condition. No task-specific reference proof enters prompts. The earlier failed readiness export remains immutable; use the syntax export with this config.

[rl/qwen_05b_completion_grpo.json](rl/qwen_05b_completion_grpo.json) uses the existing runner with the preparer's `--completion-tasks` export. Training-proof prefixes are external assistance. Frozen probes select training tasks with reward variation. Both orderings share membership and validation-controlled assistance. Original and final held-out evaluation use no proof prefix. See the [study registration](../docs/results/03_grpo_proof_pilots.md#assisted-proof-completion-2026-10-04).


[data/mathematical_rlp_review_v1.json](data/mathematical_rlp_review_v1.json) admits the reviewed generator hash for `prepare_rlp_corpus.py --controlled-mathematics`. [midtrain/qwen_05b_controlled_rlp.json](midtrain/qwen_05b_controlled_rlp.json) configures the existing RLP runner; `--inspect-data` checks tokenizer limits without loading weights or updating them. Training is disabled. [eval/mathematical_grading_v1.json](eval/mathematical_grading_v1.json) defines independent review, and [eval/mathematical_grader_calibration_v1.json](eval/mathematical_grader_calibration_v1.json) preserves private development controls. Use `scripts/eval/grade_mathematical_responses.py` for blind packets, recounts, and summaries. See [pretraining preparation](../docs/results/08_controlled_rlp.md#controlled-rlp-pretraining-preparation) for the active export and limitations.
