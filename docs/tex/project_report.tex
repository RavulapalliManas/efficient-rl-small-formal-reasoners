\begin{abstract}
This report records every experiment of the project from 1 to 8 October 2026, with the formal definitions behind them. The project asks whether reinforcement learning (RL) can teach \code{Qwen2.5-0.5B-Instruct} number theory and Lean~4 proofs under a fixed compute budget. We ran 13 experiments: data preparation, two capability baselines, three proof-RL studies with a terminal Lean reward, five knowledge-acquisition studies with an RLP reward, one evaluation series of saved checkpoints, and one RL pilot with a Lean-verified local reward. The model never produced an accepted Lean proof without assistance. Lean accepted 0 of 63 whole-proof attempts in the recounted local check, and the exported records of a larger sampling run show 0 of 273. RL with a terminal Lean reward gave no learning signal, because no sampled group had reward variation. In one RLP run, the prediction reward rose while held-out accuracy fell from 42/108 to 21/108. The only measured RL gain came from a Lean-checked witness reward on a narrow task, where validation accuracy rose from 0/8 to 6/8. A post hoc analysis shows that none of the 63 failed proof attempts was well-formed Lean~4. An audit of the Lean scorer on 9 and 10 October found nine kinds of input that it accepted and should have rejected, and a fix rejects all nine. A single tactic from a fixed list proves 28 of 420 validation statements, so a reward for accepted proofs can rise without proof skill. The Lean GRPO trainer has not run on a GPU, so no trained policy has used these weaknesses. The report ends with a proposed study that has not run.
\end{abstract}

\subsection{Findings in brief}
\begin{enumerate}
\item A terminal Lean reward gave no learning signal while the model never succeeded. This blocked \expref{4}, \expref{5}, and most of \expref{6}.
\item The unchanged model does not write well-formed Lean~4. In the 63 failed attempts of \expref{3}, 57 had a parse or file-structure error, 3 were empty, and 3 used \code{sorry} (Section~\ref{sec:posthoc}).
\item A Lean-checked reward worked once the task was small enough for the model to succeed sometimes (\expref{11}).
\item The RLP reward can rise while correctness falls (\expref{9}). Correct training targets did not make the generated reasoning correct.
\item No curriculum experiment produced a scored comparison of ordered against shuffled training.
\item AI graders disagreed on 44 of 321 response views in \expref{10}. Correctness scores without a checker are noisy.
\item Before a fix on 10 October, the scorer of the Lean GRPO trainer accepted 27 of 87 attack checks. After the fix, it accepted 0 of 87 (Section~\ref{sec:rewardaudit}).
\item A single tactic from a fixed list proves 161 of 3,450 training statements and 28 of 420 validation statements. Another 17, 3, and 3 statements in the train, validation, and test splits have hypotheses that prove \code{False} (Section~\ref{sec:rewardaudit}).
\end{enumerate}

\subsection{Lean environment and the checker}
All Lean checks use Lean \code{v4.10.0-rc1} with mathlib commit \pth{29dcec074de168ac2bf835a77ef68bbe069194c5}. This is the pair that the LeanDojo Benchmark~4 archive records. The checker accepts a candidate only if all of these conditions hold:
\begin{enumerate}
\item The target theorem statement is unchanged.
\item The file compiles without an error.
\item The target is absent from the environment before the candidate runs.
\item The proof uses only permitted axioms. \code{sorry}, \code{admit}, new axioms, and \code{native\_decide} are rejected as forbidden constructs.
\end{enumerate}
Each run that used Lean checked a true control and a false control before it scored candidates. A verifier infrastructure failure gives a null outcome, which Section~\ref{sec:signals} defines. The checker module is loaded from the run environment; its source is not in this repository. Section~\ref{sec:rewardaudit} audits the scorer of the later Lean-reward trainer, which builds on this checker.

CPU work, recounts, and evaluations of saved checkpoints ran on cpu-angad. The approved ceilings were \$10 per pilot on 3 October, \$64 in total on 4 October, and \$95 in total on 6 October. \section{Formalization}
\label{sec:formalism}

\subsection{Capability decomposition}
We decompose mathematical competence into four conditional task families. Table~\ref{tab:decomposition} lists them. These are task scores under declared support. They are not direct measurements of separate internal faculties.

For divisibility, recall of the existential definition and composition of supplied witnesses are different tasks. Given $b = ak$ and $c = bl$, the witness $w = kl$ satisfies $c = aw$. A correct product witness tests execution. Retrieval of the definition and construction of the argument without support test independent use.

\subsection{Mathematical records}
\label{sec:records}
Each verified reference derivation has one canonical record
\begin{equation}
E_i = (\Gamma_i,\, g_i,\, \mathcal{K}_i,\, G_i,\, \pi_i,\, R_i).
\label{eq:record}
\end{equation}
Here $\Gamma_i$ is the set of assumptions, $g_i$ is the goal, and $\mathcal{K}_i$ is the set of annotated mathematical prerequisites. $G_i$ is the scoped dependency graph, $\pi_i$ is the sequence of proof operations, and $R_i$ is the renderer and verifier provenance. A theorem can have more than one valid derivation. A grader must not reject a valid alternative because it differs from $G_i$.

The controlled studies use three record types:
\begin{align}
k &= (\mathrm{id},\ \mathrm{domain},\ \mathrm{statement},\ \mathrm{assumptions},\ \mathrm{prerequisites}, \nonumber\\ &\qquad \mathrm{valid\_uses},\ \mathrm{invalid\_uses},\ \mathrm{source},\ \mathrm{review\_status}), \\
o &= (\mathrm{id},\ \mathrm{input\_state},\ \mathrm{required\_conditions},\ \mathrm{action}, \nonumber\\ &\qquad \mathrm{output\_state},\ \mathrm{justification}), \\
e &= (\mathrm{id},\ \mathrm{family\_id},\ \mathrm{concept\_ids},\ \mathrm{operator\_ids},\ \mathrm{assumptions}, \nonumber\\ &\qquad \mathrm{goal},\ \mathrm{reference\_steps},\ \mathrm{dependencies},\ \mathrm{split},\ \mathrm{provenance}).
\end{align}
A knowledge item $k$ is a fact with its domain and conditions. An operator $o$ is a local transformation with its required conditions. An example $e$ is a task instance with a reference derivation. Each reference step records its claim, operation, premises, scope, and justification. Every premise of a step must be an assumption, an exposed fact, or an earlier step.

The records keep integer and natural-number domains separate. They also keep zero and sign conditions explicit. For example, modular cancellation belongs to the integers, and its coprimality hypothesis belongs to the rule. A paired invalid use omits that hypothesis and is labeled as an error.

Each record has exactly one admission status: \code{unreviewed}, \code{accepted\_by\_exact\_check}, \code{accepted\_by\_mathematical\_review}, \code{disputed}, or \code{rejected}. Only admitted records enter positive training targets. An exact arithmetic check certifies its declared computation. It does not certify a universal statement. Without Lean, a reviewed proof is mathematically reviewed, not formally certified.

\subsection{Information views}
\label{sec:views}
The model sees a rendered view $x(e, v)$ of an admitted example $e$, with
\begin{equation}
v = (m_K,\ m_S,\ \rho,\ \tau).
\label{eq:view}
\end{equation}
Here $m_K$ is the knowledge mask, $m_S$ is the structure mask, $\rho$ is the representation (numerical or symbolic), and $\tau$ is the task type. Model-visible fields contain only the rendered task and the declared support. Private fields contain the reference steps, hidden targets, review records, and scoring candidates.

Both masks are discrete intervention labels, not calibrated difficulty values:
\begin{itemize}
\item Knowledge axis $m_K$: full fact supplied, partial fact supplied, recognition alternatives, fact absent.
\item Structure axis $m_S$: local operation supplied, sequence or subgoals supplied, partial sequence, structure absent.
\end{itemize}
The two axes are not independent in practice. A subgoal can reveal a witness, which is knowledge leakage. A supplied lemma can reveal the decomposition, which is structural support. Each view records exactly which facts and hints it exposes.

With coordinates (knowledge demand, structure demand), the research plan defines three proposed paths: structure first, $(0,0) \to (0,1) \to (1,1)$; knowledge first, $(0,0) \to (1,0) \to (1,1)$; and joint, $(0,0) \to (1,1)$. These paths change both the order and the distribution of support conditions, so they are path comparisons, not order-only comparisons. None has run.

\subsection{Learning signals}
\label{sec:signals}

\paragraph{Verified binary reward.} For a task with a frozen formal obligation, let $a$ be the object extracted from the response, such as a witness expression or a proof body. The reward is
\begin{equation}
r(x, a) =
\begin{cases}
1 & \text{if Lean accepts the unchanged obligation with } a, \\
0 & \text{if Lean rejects } a \text{, or no valid object can be extracted}, \\
\bot & \text{if the verifier infrastructure fails.}
\end{cases}
\label{eq:verified}
\end{equation}
A null reward $\bot$ is excluded from updates. It is never converted to $0$. Extraction failures receive a separate format status. An accepted witness certifies the submitted object. It does not certify the explanatory prose around it.

\paragraph{RLP prediction reward.} Let $x$ be the prompt, $r$ the generated reasoning, and $y$ a hidden target span. Let $\ell_\theta(y \mid \cdot)$ be the mean teacher-forced log probability of $y$ under the policy, and $\ell_{\bar\theta}$ the same quantity under an exponential moving average (EMA) teacher. The reward is
\begin{equation}
R_{\mathrm{RLP}}(x, r, y) = \ell_\theta(y \mid x, r) - \ell_{\bar\theta}(y \mid x).
\label{eq:rlp}
\end{equation}
This objective follows the information-gain reward of RLP~\cite{rlp}. Our task-conditioned adaptation is not a reproduction of the published experiments. The reward scores how much the reasoning raises the likelihood of the target. It does not score whether the reasoning is correct.

\paragraph{Group-relative advantage.} For one prompt, the trainer samples $G$ responses $r_1, \dots, r_G$ with rewards $R_1, \dots, R_G$. The group-relative advantage is
\begin{equation}
A_j = \frac{R_j - \bar{R}}{s_R + \varepsilon}, \qquad \bar{R} = \frac{1}{G}\sum_{k=1}^{G} R_k,
\label{eq:adv}
\end{equation}
where $s_R$ is the group standard deviation of the rewards and $\varepsilon > 0$ is a small constant~\cite{trl}. Two consequences follow from Equations~\eqref{eq:rlp} and~\eqref{eq:adv}.

First, the teacher term cancels. Within a group, $\ell_{\bar\theta}(y \mid x)$ is the same for every response, so
\begin{equation}
R_j - \bar{R} = \ell_\theta(y \mid x, r_j) - \frac{1}{G}\sum_{k=1}^{G} \ell_\theta(y \mid x, r_k).
\end{equation}
The standard deviation $s_R$ is also unchanged by a common shift. Therefore the EMA teacher does not act as a penalty that keeps the policy near its start. The runner used no KL reference penalty in the RLP studies.

Second, a group without reward variation gives no learning signal. If $R_1 = \dots = R_G$, then $A_j = 0$ for every $j$. Without a reference penalty, the policy-gradient term for that group is zero. With the binary reward of Equation~\eqref{eq:verified}, a group of all failures is such a group. For a binary reward with success probability $p$ per sample, the probability that a group has variation is
\begin{equation}
P_{\mathrm{mix}}(p, G) = 1 - p^{G} - (1-p)^{G}.
\label{eq:pmix}
\end{equation}
With $G = 4$, $P_{\mathrm{mix}} = 0.185$ at $p = 0.05$ and $0.875$ at $p = 0.5$.

\paragraph{Readiness gate.} Before any optimizer update, sample the unchanged policy on the frozen training pool. Let $\mathcal{G}$ be the set of sampled groups. Define the mixed-group fraction
\begin{equation}
\phi_{\mathrm{mix}} = \frac{\left|\{\, g \in \mathcal{G} : \text{group } g \text{ contains both accepted and rejected responses} \,\}\right|}{|\mathcal{G}|}.
\end{equation}
A run proceeds only if $\phi_{\mathrm{mix}} > 0$ across more than one task family. Report the entire pool, including unsolved tasks. Do not select a favorable subset and call it readiness.

\subsection{Curriculum formalism}
\label{sec:curriculum}
A curriculum experiment has the following parts.
\begin{enumerate}
\item A concept graph $\mathcal{C} = (V, D)$. The nodes $V$ are concepts, and an edge $(u, w) \in D$ states that $u$ is a prerequisite of $w$. Each edge records its provenance: authored, reviewed, annotation-derived, or Lean-checked.
\item A pool of items. Each item has an identifier, its concepts, a split, a task type, and a success check.
\item An ordered list of support levels $s_1 \succ s_2 \succ \dots \succ s_L$, from most to least support.
\item A presentation multiset $\Pset = \{\, (e,\ v,\ j) \,\}$, where $e$ is an example, $v$ is a view, and $j$ is a repeat index. A repeat with $j > 0$ is a replay.
\item An arm $a$, defined by an order function $\sigma_a$ that maps $\Pset$ to a sequence.
\item A fading rule. It is either a fixed schedule, or a rule that lowers support only when curriculum validation passes a declared threshold. All arms share the rule.
\item The readiness gate of Section~\ref{sec:signals}.
\item Endpoints. Each endpoint states its measure, its denominator, its phase, and its artifact.
\end{enumerate}

An order-only study compares a treatment arm with a control arm. It must satisfy these invariants:
\begin{enumerate}
\item Both arms consume the same multiset $\Pset$, including replay occurrences.
\item Both arms start from the same checkpoint, with the same reward, optimizer, precision, and resource caps.
\item Training, curriculum-validation, and final-evaluation items stay in separate splits. All views and paraphrases of an example family stay in its split.
\item No final-evaluation item enters training, prompts, retrieval, or adaptive sampling.
\item A study that changes the distribution of support conditions is a path comparison, not an order-only comparison.
\end{enumerate}

The experiments used two controls. A per-pass permutation shuffles the order inside each pass over the pool, so membership per pass is identical between arms. A global permutation shuffles the whole sequence $\Pset$ with a fixed seed, so only the total multiset is identical; a presentation without support can then come before the same example with full support. These controls test different hypotheses, and a study must name which one it uses.

\subsection{Evaluation formalism}
\label{sec:evaluation}
Knowledge acquisition means improved recall and application of exposed facts on fresh tasks, without those facts supplied at evaluation. Operator learning means improved valid transformations when the required mathematics is supplied. Proof composition means valid combinations of these transformations on unfamiliar dependencies. Delayed retention tests acquisition after intervening updates on other material.

Let $C$ be the set of concept families, and let $n_c$ be the number of unassisted application items for concept $c$. The primary score of the controlled study is the concept-macro full correctness
\begin{equation}
F = \frac{1}{|C|} \sum_{c \in C} \frac{1}{n_c} \sum_{i=1}^{n_c} \mathrm{full\_correct}[c, i].
\label{eq:primary}
\end{equation}
Unknown grades count as failures in this conservative score, and their frequency is reported. Truncated responses stay in the denominators. The treatment effect of an order study is $\Delta = F_{\mathrm{ordered}} - F_{\mathrm{shuffled}}$, reported with each arm's change from the unchanged checkpoint. The interval for $F$ uses a paired concept-cluster percentile bootstrap with 10{,}000 draws and seed 20261006. This interval describes the authored corpus, not variation across training seeds.

The decision rules are fixed in advance. The exploratory progression threshold is a concept-macro gain of 0.10; it is not a power calculation. Delayed retention requires a nonzero success count before the interlude and zero lost successes after it. Checkpoint selection maximizes $F$ on curriculum validation among checkpoints that satisfy retention, with ties to the earliest. Final-test results cannot change the selection, and the RLP reward alone cannot select a checkpoint.

Each graded response returns \code{fact\_correct}, \code{conditions\_correct}, \code{operations\_correct}, \code{conclusion\_correct}, \code{core\_score}, \code{full\_correct}, \code{first\_error\_step}, \code{error\_category}, \code{uncertain}, \code{reason}, and \code{evidence}. Graders accept valid alternative methods and conventional notation. They cannot supply a missing central lemma or repair an invalid central argument. A correct conclusion reached through invalid reasoning fails full correctness.

\section{Data and capability baselines}
\label{sec:baselines}

\subsection{\expref{1}: LeanDojo subset and number-theory pool}
\paragraph{Question.} Which Lean theorems can serve as training, curriculum-validation, and held-out items, without overlap between splits?

\paragraph{Method.} We filtered LeanDojo Benchmark~4~\cite{leandojo} to declared arithmetic and number-theory source files and kept the official \code{random} split membership. The filter excluded declarations with listed types or ambiguous proof syntax. It removed training declarations whose normalized statements overlap validation or test statements, and training declarations that reference a validation or test theorem. Evaluation exports keep headers, imports, and source locations, and omit proofs. A broader pool used the same curator with logic, sets, functions, relations, integer arithmetic, and more number-theory families.

\paragraph{Result.} Table~\ref{tab:data} gives the counts. The Nat training split has 447 theorems with tactic traces and 1,312 tactic records. The broader training pool has 1,350 theorems with traces and 5,233 tactic records, and 1,402 annotated references between training theorems.

\section{Knowledge acquisition with the RLP reward}
\label{sec:rlp}

Experiments~7, 8, 9, and 13 trained with the RLP reward of Equation~\eqref{eq:rlp} through the TRL GRPO trainer, with learning rate $10^{-6}$, EMA teacher decay 0.999, and no KL penalty. Experiment~12 audited the training data of \expref{9}. No experiment in this section used a Lean reward.

\subsection{\expref{7}: RLP training and primitive-first continuation}
\paragraph{Question.} Does RLP training on number-theory text improve number-theory answers?

\paragraph{Method.} The first stage trained the Instruct model on chapters of an openly licensed algebra textbook (Judson, AATA), with four samples per group, a 128-token completion cap, and a 256-token context. The continuation loaded that policy and its teacher, and trained on project-authored text about primitives, witnesses, induction, contradiction, and primes, placed before the textbook contexts. Continuation evaluations supplied an answer-format prefix.

\paragraph{Result.} The first stage ran 256 optimizer steps over 1,024 rollouts and generated 117,972 training tokens. Its arithmetic evaluation accepted 0 of 32 answers before and after training, and all 32 answers lacked a parseable boxed answer both times. The continuation generated 127,389 training tokens, for 245,361 across both stages. Held-out arithmetic and prime questions scored 11/48 before and after. Prime curriculum validation scored 7/16 before, after, and at every intermediate evaluation. The final policy is saved in S3 under \code{number\_theory\_rlp\_20261004\_continuation/}.

\subsection{\expref{8}: Precision audit and FP32 rerun}
\paragraph{Question.} Did the continuation update the weights at all?

\paragraph{Method.} A CPU audit compared every stored parameter of the continuation with its parent, inspected the optimizer state, and ran controlled AdamW updates on the saved weights. A rerun then repeated the continuation from the same parent, teacher, data, seed, and limits, with FP32 parameters and optimizer moments and BF16 computation. Precision was the only intervention.

\paragraph{Result.} Only 8,557,971 of 494,032,768 parameter entries changed in the continuation. The saved optimizer moments were BF16, with no FP32 master weights. On identical saved weights with constant nonzero gradients, a BF16 control changed 660 of 65,536 entries, while the FP32 control changed every sampled entry. Both zero-gradient controls left the weights unchanged. In the FP32 rerun, the first update changed sampled weights with FP32 moments. Held-out accuracy stayed at 11/48, and validation went from 7/16 to 6/16. The rerun generated 125,411 training tokens.

\paragraph{Interpretation.} The controls show that BF16 rounding discarded small updates in the original setup. The rerun shows that working updates still gave no accuracy gain. The audit does not measure how much the rounding loss contributed to the original null result.

\subsection{\expref{9}: Primitive RLP curriculum}
\paragraph{Question.} Does RLP on authored primitive tasks, presented in dependency order, improve unassisted answers?

\paragraph{Method.} The run started from the original Instruct model, not from \expref{7}. It trained on 448 unique authored tasks, from witnesses and substitution through gcd, Bézout coefficients, inverses, primes, and congruences. Replay of earlier tasks expanded them to 596 presentations, one per optimizer step, with eight samples per group and a 512-token response limit. Training prompts supplied definitions. The reward scored a hidden integer target span after the scorer appended a boxed-answer prefix. Evaluation removed the definitions and required the model to write the answer. Curriculum validation had 56 items and the held-out set had 108.

\subsection{What the trainer pays}
\label{sec:rewardpays}
By Equation~\eqref{eq:verified}, the trainer gives reward 1 when the scorer accepts a completion, and 0 otherwise. The function \code{verify\_group} returns the verdict. The trainer, the probe (\pth{scripts/eval/probe_nt_pool.py}), and the pass-rate map (\pth{scripts/eval/pass_rate_map.py}) call it. It accepts a completion only if all of these hold:
\begin{enumerate}
\item The completion has no match of the pattern \code{FORBIDDEN}. A match gives a rejection without a Lean call.
\item The completion is not empty, and every line is indented.
\item The fixed prefix, the supplied steps, and the completion parse as one command.
\item Lean reports no error within 20 seconds. A timeout or a REPL crash is a rejection.
\item The target guard \code{TARGET\_ABSENT} of the checker passes.
\item One info message sits at the line of the checker's \code{\#print axioms} command and names the target. It lists only \code{propext}, \code{Classical.choice}, and \code{Quot.sound}.
\end{enumerate}
The REPL is the Lean read-eval-print loop (leanprover-community/repl, tag \code{v4.10.0-rc1}). It checks each completion as one command in a loaded environment. The pattern \code{FORBIDDEN} is in \pth{scripts/eval/probe_start_depth.py}. It matches the words \code{sorry}, \code{admit}, \code{axiom}, \code{unsafe}, \code{native\_decide}, \code{set\_option}, \code{run\_tac}, \code{run\_conv}, \code{by\_elab}, \code{run\_cmd}, \code{run\_elab}, and \code{run\_meta}. It matches the symbol \code{\#}. It also matches \code{exact?}, \code{apply?}, \code{rw?}, \code{rw\_search?}, \code{hint}, and \code{library\_search}.

\subsection{Valid proofs of statements without information}
\label{sec:trivial}
These entries need no scorer exploit. Lean accepts the proof, and the proof is correct. The reward measures the statement, not the policy.

\paragraph{Single-tactic statements (T1).} A \emph{single-tactic statement} is a statement that one tactic from a fixed list of nine proves. The list is \code{aesop}, \code{tauto}, \code{simp\_all}, \code{omega}, \code{norm\_num}, \code{simp}, \code{rfl}, \code{linarith}, and \code{decide}. Of 3,450 train statements, 161 (4.7\%) are single-tactic statements. 393 of 31,050 candidates were accepted. By tactic, the accepted train candidates are \code{aesop} 97, \code{tauto} 73, \code{simp\_all} 71, \code{omega} 60, \code{norm\_num} 31, \code{simp} 30, \code{rfl} 14, \code{linarith} 9, and \code{decide} 8. Of 420 validation statements, 28 (6.7\%) are single-tactic statements, with 55 of 3,780 candidates accepted. On 200 train statements, the SFT model solved 0 (0 of 1,600 samples), and the nine single tactics solved 8 (24 of 1,800 candidates). On the LeanDojo validation set, the SFT model solved 3 of 43 theorems at 8 samples, and all 3 lie inside the 9 theorems that single tactics solve.

A policy that learns to emit \code{omega} or \code{simp\_all} first would gain reward on these statements with no proof skill. At $n = 420$, an exact two-sided McNemar test at $\alpha = 0.05$ needs 6 newly solved statements and 0 losses. The 28 single-tactic validation statements exceed that floor. The primary metric of the midsemester study is therefore the 392 validation statements that no single tactic proves, reported next to the full 420. The RL pool holds 0 single-tactic statements. One drawback remains: the SFT problems still hold 99 of them, so the SFT model trains on their proofs.

A statement is vacuous when one candidate is accepted. Two synthetic controls checked the sweep. With $n \in \mathbb{N}$, the statement with hypothesis $n < 0$ and goal $n = 5$ was accepted by 8 of 8 tactics, and the statement with hypothesis $n < 3$ and goal $n < 5$ was rejected by 8 of 8. All 17 vacuous train statements have proofs in \pth{nt_sft_v2}, and all 3 vacuous validation statements lie among the 28 single-tactic validation statements. The sweep has two limits. Detection is incomplete: 16 statements had a timeout or a REPL crash and no accepted candidate, and they stay in the data. Also, \code{exfalso} does not introduce premises inside the goal, so the sweep tests only the hypotheses before the colon.

\subsection{Valid proofs that the policy can recall}
\label{sec:recall}
These entries need no scorer exploit. Reward rises because the policy recalls content, not because it proves something new. \emph{Contamination} is evaluation content in the training data, the prompts, or the RL tasks. The \emph{token Jaccard similarity} of two statements $a$ and $b$ is $J(a, b) = |T_a \cap T_b| / |T_a \cup T_b|$, where $T$ is the set of tokens of the statement text without its name and proof. A \emph{near-duplicate} pair has $J$ at or above a stated cap.

\paragraph{Task bank overlap (L1).} 826 of the 1,007 accepted tasks of task bank v1 lie in the 26 LeanDojo evaluation files. 1,137 of its 1,350 records lie there. Task bank v3 had 0 of 4,632 records in evaluation files at the time of the check. RL tasks now come only from files outside the evaluation files.

\paragraph{Near-duplicates (L2).} The split key hashes statements after it renames variables. It misses hypothesis-name and parenthesis variants. The token scan found 68 train statements at $J = 1.00$ to a validation or test statement. 13 of them are SFT problems. The key had missed all 68. Splits v3 exclude train statements at $J \ge 0.85$ to a validation or test statement, and at $J \ge 0.7$ to a miniF2F statement. They exclude 165 near-duplicates of a test statement, 127 of a validation statement, 34 of a miniF2F statement, 17 vacuous statements, and 16 miniF2F-check names. One statement can have several reasons. A cap leaves close statements below it: in splits v2, 192 of 420 validation statements have a train neighbour between 0.70 and 0.85. Report validation results by nearest-train-similarity band. The miniF2F statement \code{aime\_1994\_p3} equals \pth{lean_workbook_plus_44384} up to hypothesis names, and that statement and \pth{lean_workbook_plus_59411} are miniF2F near-duplicates that \pth{nt_sft_v2} contains.

\paragraph{Copying the nearest training proof (L3).} \pth{scripts/eval/nearest_proof_baseline.py} takes no model. It pastes the Lean-accepted proofs of the 8 nearest train statements under each validation header. Table~\ref{tab:nearest} gives the counts. 5 of the 22 non-trivial solves copy a train statement at $J = 1.0$. All 5 neighbours have proofs in \pth{nt_sft_v2}. A model trained on \pth{nt_sft_v2} therefore saw proofs that copy-solve 5 validation statements, and its validation numbers need this caveat. The baseline pastes bodies verbatim. Renaming hypotheses would likely solve more, and we did not test it. Report this baseline next to every arm.

\subsection{Weaker checks that accept a non-proof}
\label{sec:weaker}
\paragraph{REPL tactic mode (W1).} The tactic mode of the REPL has no axiom check. In the step-level search over LeanDojo theorems, 9 closed paths for \code{Set.union\_diff\_left} in \pth{search_v1_sftfinal} were rejected on re-check, because the proofs use a lemma whose proof had been replaced by \code{sorry}. The GRPO reward uses the environment mode of the REPL, which checks axioms. It agrees with the subprocess check on 160 of 160 proofs. Every found proof needs an axiom check on re-check.

\paragraph{Old subprocess check (W2).} The function \code{check} in \pth{scripts/eval/probe_start_depth.py} reads axioms from the whole Lean output and has no one-command check. By code reading, it keeps five exploits: \pth{trace_fake_no_axioms}, \pth{trace_fake_axiom_list}, \pth{command_elab_override}, \pth{trailing_theorem}, and \pth{namespace_shadow}. This was not tested. Three scripts call it: \pth{lean_eval_statements.py}, \pth{single_tactic_baseline.py}, and \pth{search_tactics.py}. The 9/43 baseline and the 3/43 SFT result come from them, and the re-scoring of Table~\ref{tab:rescore} does not list those runs. Do not use these scripts to score model output until they call \code{verify\_group}.

\paragraph{Batch-file check (W3).} The function \code{check\_batch} in \pth{scripts/data/verify_external_proofs.py} reads each axiom report by line, so the forged reports of S1 and S2 cannot work there. It has no one-command check. It scores external proofs only, not model output.

\subsection{Reward that covers part of the output, and reward noise}
\label{sec:partial}
\paragraph{Witness-only reward (R1).} In \expref{11}, Lean checked one witness. Correct witnesses on validation rose from 0/8 to 6/8, and error-free answers were 2/8 on validation and 0/4 held-out. The explanations around the witness often stayed wrong.

\paragraph{Constant answers (R2).} The corpus audit of \expref{12} found that a constant answer solved every contradiction item. On the answer-task validation set, a constant answer scores 14/309: \code{gcd} 5/45, \code{pow\_mod} 6/45, \code{mod\_inverse} 2/45, and \code{witness} 1/45. A random answer scores 0/309.

\paragraph{No-op tactics (R3).} A per-step reward would credit the fraction of generated tactics that elaborate before the first error. Tactics that elaborate and change nothing, for example \code{skip} or \code{have h := h}, would earn it. A subgoal reduction is not a proof. The planned control counts a tactic only if the goal state changes, keeps the per-step weight below the proof weight, and reads the ten highest-reward samples each round. None of this is implemented.

\paragraph{RLP reward and accuracy (R4).} In \expref{9}, the RLP reward rose while held-out accuracy fell from 42/108 to 21/108. The reward is heuristic and has no Lean check. A train and evaluation mismatch is a possible cause, and no test isolated it.

\paragraph{Batch-file neighbours (N1).} A candidate that ended after \code{by} or a bullet made Lean report the parse error in the next candidate's span. An unterminated block comment swallowed the rest of its file. In one test, 15 of 40 known-good proofs were rejected. The probe now scores with the REPL path. Re-scoring 1,229 old probe verdicts gave 0 flips.

\paragraph{Timeouts (N2).} 7 of 1,689 SFT proofs need more than the 20-second limit under the load of cpu-angad. At a 120-second limit they take 24.6 to 84.1 seconds each. The single-tactic checks gave 23 timeouts and 11 REPL crashes in 31,050. The scorer gives reward 0 to a timeout and to a crash, whereas Equation~\eqref{eq:verified} reserves $\bot$ for verifier failure. A policy that avoids slow tactics would gain reward. This is an inference, not a measurement.

\paragraph{Length cap (N3).} 253 of 1,600 first errors (15.8\%) of the SFT model were the 256-token cap. A binary reward pays outputs that stop early.

\subsection{Checks before an RL gain counts, and open items}
\label{sec:rewardchecks}
\paragraph{Checks.} Run these before any RL gain is reported:
\begin{enumerate}
\item Split the solved set of every arm into single-tactic, vacuous, near-duplicate, and other statements. Report the rate on the other statements as the headline.
\item Report the nearest-proof baseline of Table~\ref{tab:nearest} next to every arm.
\item Run \pth{scripts/eval/check_checker_attacks.py} on the final scorer. Require 0 accepted attacks and all controls accepted.
\item Run \pth{scripts/eval/rescore_accepted.py} on every accepted proof of the final run, and read the scan hits.
\item Read the highest-reward samples of each round.
\item Run the shuffled-reward arm. It keeps the reward rate and the share of mixed groups, and it breaks the link between a completion and its reward. A \emph{mixed group} holds both a reward of 0 and a reward of 1.
\item Report the cap rate, the mean length, and the timeout count per arm.
\end{enumerate}

\paragraph{Open items.} These come from the trainer-and-checker report. As of 10 October, the decision log of \pth{docs/EXPERIMENTS.md} has no line on items 1 to 4 and 6.
\begin{enumerate}
\item Accept the three scorer rules as the reward check for every arm.
\item Retire the old subprocess check, or move its three users to \code{verify\_group}.
\item Decide whether \code{observe} joins \code{FORBIDDEN}.
\item Keep the 20-second timeout, or raise it and pay more Lean time per step.
\item Use the new SFT data for the midsemester arms, or report the caveat of Section~\ref{sec:recall}.
\item Add a dated line to the decision log of \pth{docs/EXPERIMENTS.md} for the scorer change and for the removal of the Bernoulli random-reward arm.
\end{enumerate}

\paragraph{Remaining risks.} The REPL has no memory cap of its own, so a large computation can allocate memory before the 20-second timeout. Every job needs a systemd \code{MemoryMax}. Two older copies of \code{FORBIDDEN} remain, in \pth{scripts/data/replay_training_proofs.py} and \pth{scripts/data/build_sft_data.py}. They define weaker patterns and filter data. They do not score reward.

\section{What the record shows}
\label{sec:findings}

\paragraph{The cold start blocked every terminal-reward study.} Equation~\eqref{eq:adv} gives zero advantage to a group of all failures, and Equation~\eqref{eq:pmix} shows how fast such groups dominate as the success rate falls. Experiments~4 and~5 had no successes. \expref{6} created successes only with most of the proof supplied. Section~\ref{sec:posthoc} shows that the unchanged model did not produce well-formed Lean~4, so the barrier came before the mathematics.

\paragraph{A verified reward works on a task the model can sometimes solve.} \expref{11} narrowed the task to one supplied local operation. Groups then had variation, and validation accuracy rose from 0/8 to 6/8. The explanations around correct witnesses often stayed wrong, so the reward certified the submitted object only.

\paragraph{The prediction reward does not track correctness.} In \expref{9} the reasoned target likelihood rose while held-out accuracy halved. In the preparation of \expref{13}, a deliberately false reasoning prefix raised the target likelihood in both inspected examples. RLP gave no accuracy gain in Experiments~7, 8, 9, or 13.

\paragraph{No curriculum comparison has a result.} Three studies had no reward variation, one selected a single task, two had no control arm, and one has an unscored control. Every prerequisite edge so far was authored by the team or derived from annotations. No experiment tested whether a prerequisite helps a later concept.

\paragraph{Grading without a checker is noisy.} AI reviewers disagreed on 44 of 321 views in \expref{10}, and the primitive RLP corpus contained shortcut tasks (\expref{12}). This motivates Lean-checked endpoints where they exist.

\paragraph{A Lean-checked reward is not a proof of skill.} Section~\ref{sec:rewardaudit} shows two limits. Before a fix on 10 October, the scorer of the Lean GRPO trainer accepted 9 kinds of input that are not proofs of the target. After the fix, it accepted none of the 29 attacks. Separately, a single tactic from a fixed list proves 28 of 420 validation statements, and copying the nearest training proof solves 22 of the 392 others. A rise in the accepted rate needs a split by statement type before it counts as proof skill.

\subsection{Threats to validity}
\begin{itemize}
\item Samples are small. Validation sets have 8 to 56 items, the Nat test split has 15 theorems, and the false-prefix result rests on 2 examples.
\item Each run used one training seed, so no result has a seed-to-seed interval.
\item Several evaluation sets were reused across experiments and became development material.
\item Pretraining exposure of the model to mathlib and to the authored concepts is unknown.
\item No run measured GPU-active time, so cost comparisons use tokens and Lean calls only.
\item The GPU sampling counts of \expref{3} come from an exported monitoring stream. Nobody recounted them independently.
\item The counts of Section~\ref{sec:rewardaudit} come from run reports on cpu-angad. Nobody re-read them from the raw files.
\item The attack list of Section~\ref{sec:rewardaudit} holds 29 inputs. A count of zero accepted attacks does not show that the scorer is sound.
\end{itemize}

\section{Proposed next study (not run)}
\label{sec:proposed}
This section states a plan. Nothing in it has run, and its predictions are declared before any data.

\paragraph{Question.} Under a fixed Lean-call budget, which gives more held-out Lean proofs for a 0.5B model: a curriculum that keeps the success rate near one half, or a reward that credits individual tactics?

\paragraph{Stages.} The plan has four stages:
\begin{enumerate}
\item Supervised training on Lean~4 proofs at the pinned version, so that the model writes well-formed Lean. The parse rate and the elaboration rate on held-out statements decide when this stage ends.
\item Expert iteration: sample proofs on fixed statements, keep the proofs that Lean accepts, and fine-tune on them~\cite{polu2022}. RLP on the same corpus enters only if it beats supervised training alone at equal compute.
\item GRPO with the binary reward, once the readiness gate passes.
\item A comparison of GRPO with expert iteration at the same number of Lean calls. On informal mathematics, Havrilla et al.\ report that ``all algorithms perform comparably, with Expert Iteration performing best in most cases''~\cite{havrilla2024}.
\end{enumerate}

\paragraph{Curriculum.} A reverse curriculum gives the model a reference proof prefix and asks for the rest, then moves the starting point back toward the theorem statement~\cite{r3}. The arms are: no curriculum; a staged schedule; all depths mixed; and an adaptive rule that keeps each theorem near a success rate of one half. In the R3 study, the mixed schedule beat the staged one~\cite{r3}. The adaptive arm changes the distribution of support levels, so it is a path comparison under Section~\ref{sec:curriculum}.

\paragraph{Reward distribution.} Lean marks the first failing tactic, and tactic-level rewards with first-error propagation outperformed outcome-only rewards in most settings of Kim and Yun~\cite{kim2026}. A tactic-level term is heuristic. A reward for valid Lean alone is open to gaming, for example by repeated \code{try simp}, and a compile-only reward in autoformalization led the model to emit the same simple, irrelevant statement for every problem~\cite{formarl}. Any such term must stay below the value of one accepted proof.

\paragraph{Endpoints and prediction.} The primary endpoint is held-out whole-theorem proofs per 1{,}000 Lean calls. The secondary endpoint is $\phi_{\mathrm{mix}}$ per training step. We predict that the curriculum helps most when the reward is outcome-only. Loop decisions use curriculum validation only, and the test set is scored once. From 0 of 15, an exact McNemar test needs 6 newly solved theorems for $p < 0.05$, so the larger pool with 38 test theorems is the better held-out set.

\paragraph{Preparation.} Lean must first replay the 860 linear proofs and every cut point. Then the pass rate at each starting point is measured for the unchanged model.
