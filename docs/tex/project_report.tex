\begin{abstract}
This report asks whether reinforcement learning (RL) can teach a small language model, \code{Qwen2.5-0.5B-Instruct}, to write Lean~4 proofs of elementary number theory.
We formulate proof writing as a Markov decision process (MDP) with a reward of 1 only for a complete proof that Lean accepts.
Most experiments failed for one main reason: when Lean accepts no attempt, the RL update is exactly zero.
RL helped only on theorems that the model could already prove some of the time.
We also found ways to obtain the reward without proof skill, and several engineering faults.
\end{abstract}

\noindent\fbox{\parbox{\dimexpr\textwidth-2\fboxsep-2\fboxrule}{
\textbf{Main findings}
\begin{enumerate}[leftmargin=*]
\item RL needs some accepted attempts. With no accepted attempt, the gradient is zero (Section~\ref{sec:zero}).
\item The first barrier was the Lean language, not the mathematics (Section~\ref{sec:cold}).
\item A reward that does not check correctness can increase while accuracy decreases (Section~\ref{sec:rlpexp}).
\item RL helped twice, both times on theorems that the model could already prove some of the time (Sections~\ref{sec:local} and~\ref{sec:interactive}).
\item A Lean acceptance does not always show skill: the checker had faults, and some statements are trivial (Section~\ref{sec:cheat}).
\item The plan recorded on 13 October uses a corrected environment, a curriculum ordered by proof structure, and a cleaned held-out panel (Section~\ref{sec:next}).
\item In the runs of 18 and 19 October, filtered and curriculum-ordered RL again raised acceptance only on their training theorems, in one run each. No arm showed a detected held-out gain over S (Section~\ref{sec:oct19-results}).
\item A read-only analysis of these runs finds no sign of a fault in the RL update: on the 62 \code{RL\_filtered} theorems, acceptance rises from 0.306 to 0.597. The reward is rarely nonzero: R's first visit finds a proof on 46 of 506 TRAIN theorems. RL concentrates on \code{simp\_all} actions with a lemma list. On the selection set, 326 of \code{RL\_filtered}'s 328 first actions start this way, and Lean rejects 224 of them at the first tactic. No run tests this account (Section~\ref{sec:oct20-why}).
\end{enumerate}

\section{The problem}
\label{sec:problem}

We want a small language model that writes proofs that the proof assistant Lean~4 can check.
The topic is school and early-university number theory: parity, divisibility, gcd and lcm, primes, and congruences.
The midterm goal was a model that produces some complete proofs that Lean accepts.
The goal for the end of the semester is proof strategy on competition-style theorems.

\paragraph{Motivation.}
\begin{enumerate}
\item \textbf{Efficiency.} We want the most proofs for a fixed compute budget. We study the \emph{curriculum} (which theorems, in which order) and the \emph{distribution of reward} over the actions of a proof.
\item \textbf{Checked learning.} A model that learns without a checker can learn false statements. Lean should check the model while it learns, not only at the end.
\item \textbf{One model for informal and formal reasoning.} The model writes a short informal argument and then its Lean tactic. A separate translator would add errors and compute.
\item \textbf{No human graders.} Lean gives an exact reward. This setting is called RL with verifiable rewards (RLVR). The reward is \emph{sparse}: a signal comes only from a complete proof.
\end{enumerate}

\paragraph{What Lean does.}
A Lean theorem has a statement and a proof.
We write the proof as a list of \emph{tactics}.
Each tactic changes the \emph{goals}, the facts that remain to be proved.
When no goals remain, the proof is complete.
Table~\ref{tab:example} shows a small example that we wrote to explain the idea, and Figure~\ref{fig:checker} shows when Lean accepts a proof.

\section{Formulation as an MDP}
\label{sec:mdp}

An MDP describes an agent that acts step by step~\cite{suttonbarto}.
At step $t$, the agent observes a state $s_t$, selects an action $a_t$, receives a reward $r_t$, and moves to a state $s_{t+1}$.
Here the agent (the \emph{policy} $\pi_\theta$) is the language model, and the environment is Lean.
We used two formulations, which differ only in the size of one action (Figure~\ref{fig:formab}).

Version 1 has three defects.
The model does not see the remaining actions, the theorem, or the proof so far.
With an action limit that the model cannot see, the process is not exactly Markov.
One error ends the episode.
Version 2 replaced the terminal-error transition with a self-loop and a fuller state; version 2.1 added tactic chunks and harness backtracking (Tables~\ref{tab:mdp-v2} and~\ref{tab:mdp-v21}).
Version 2.2 fixed the deployed interface (Table~\ref{tab:mdp-v22}).
Section~\ref{sec:next} gives the reasons for each change.

\subsection{Learning algorithm}
We maximize the expected return $J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}\big[\sum_t \gamma^t r_t\big]$.
The only reward is at the end, so the return of an episode $\tau$ is $R(\tau) \in \{0, 1\}$.
For one theorem, we sample $G$ episodes (one episode is one attempt) and use the REINFORCE estimator~\cite{williams1992}
\begin{equation}
\nabla_\theta J(\theta) \approx \frac{1}{G}\sum_{i=1}^{G} A_i \, \nabla_\theta \log \pi_\theta(\tau_i).
\label{eq:pg}
\end{equation}
The \emph{advantage} $A_i$ compares attempt $i$ with the other attempts.
The interactive runs use the leave-one-out baseline (RLOO)~\cite{ahmadian2024}, and the whole-proof runs use GRPO~\cite{shao2024,trl}:
\begin{equation}
A_i^{\text{RLOO}} = R_i - \frac{1}{G-1}\sum_{j \neq i} R_j, \qquad
A_i^{\text{GRPO}} = \frac{R_i - \bar R}{s_R + \varepsilon},
\label{eq:rloo}
\end{equation}
where $\bar R$ and $s_R$ are the mean and standard deviation of the $G$ rewards.

\subsection{Main consequence: no accepted attempt, no learning}
\label{sec:zero}
If all $G$ attempts fail, every $R_i = 0$, so every $A_i = 0$, and the update in Equation~\eqref{eq:pg} is exactly zero.
The same is true when Lean accepts all attempts.
The model learns only from \emph{mixed groups}, which contain at least one accepted and one rejected attempt (Figure~\ref{fig:groups}).

If Lean accepts each attempt with probability $p$, a group of $G$ independent attempts is mixed with probability
\begin{equation}
P_{\text{mix}}(p, G) = 1 - p^{G} - (1-p)^{G}.
\label{eq:pmix}
\end{equation}
Figure~\ref{fig:pmix} shows that this probability is small when $p$ is small.
This equation explains most of our failures.

\subsection{A second reward: RLP}
\label{sec:rlp}
Some experiments used the RLP reward~\cite{rlp} instead of Lean.
For a question $x$, reasoning $c$, and known answer $y$, the reward is $\log p_\theta(y \mid x, c) - \log p_{\bar\theta}(y \mid x)$, where $p_{\bar\theta}$ is a slowly updated copy of the model.
The reward is high when the reasoning makes the correct answer more probable.
It does not check whether the reasoning is correct (Figure~\ref{fig:rewards}).
We call it a \emph{heuristic} reward.

\paragraph{Curricula.}
RL needs theorems that the model can prove some of the time.
A \emph{curriculum} starts with easier versions of a theorem.
We made theorems easier to prove in three ways: we supplied knowledge in the prompt, we supplied part of the proof (a \emph{reverse curriculum}~\cite{r3}, Figure~\ref{fig:reverse}), or we asked for one action instead of a whole proof.
Most known proofs are short: 85\% of the linear tactic proofs in our LeanDojo pool have one or two tactics, and only 24 have five or more.
Therefore a reverse curriculum on these proofs has few levels.
To test whether \emph{order} matters, an \emph{ordered} arm and a \emph{shuffled} arm receive the same theorems the same number of times.
Table~\ref{tab:curricula} lists the curriculum of each experiment.

\subsection{Data, baseline, and the unchanged model (Experiments 1 to 3)}
\label{sec:cold}
Experiment~1 selected a number-theory subset of LeanDojo.
Its authors report that the random split overestimates performance~\cite{leandojo}, so we later built stricter splits (Figure~\ref{fig:splits}).
Experiment~2 tested the base model on school mathematics: 9 of 24 GSM8K and 3 of 20 MATH number-theory problems.
A small fine-tune lowered the held-out loss, but the scores became 8 of 24 and 3 of 20.
A lower loss did not mean better answers.

Experiment~3 asked the unchanged model to prove 21 statements.
Lean accepted 0 of 63 local attempts and 0 of 273 GPU attempts.
Figure~\ref{fig:exp3} shows that no attempt reached the mathematics.
A pattern match found old Lean~3 syntax in 33 of the 63 attempts.
In 34 of the 63, the model wrote a new theorem when we asked only for a proof.
The first barrier is the language (\emph{tested}: the classification reads Lean's error messages).

\subsection{Whole-proof RL from the unchanged model (Experiments 4 to 6)}
\label{sec:terminal}
We ran GRPO in Formulation A with $G = 4$.
In Experiment~4, Lean accepted no proof, no group was mixed, and the gradient was zero for all 32 optimizer updates.
Validation stayed at 0 of 8 theorems.
In Experiment~5, easier hand-written theorems gave 0 of 256 accepted proofs, so we did not train.
In Experiment~6, with one expression missing from a given proof, Lean accepted 2 of 64 attempts, but only one theorem gave mixed groups, and held-out attempts stayed at 0 of 16.

\emph{Why it failed} (\emph{tested}): every group had reward 0, so every update was 0 (Section~\ref{sec:zero}).
Therefore Experiment~4 gives no information about curriculum order.

%----------------------------------------------------------------------
\subsection{RL with a reward that does not check correctness (Experiments 7 to 10, 12, 13)}
\label{sec:rlpexp}
Lean gave no signal, so we tried to teach knowledge first with the RLP reward.
\begin{itemize}
\item Experiment 7 (textbook text): held-out accuracy was 11/48 before and after.
\item Experiment 8: only 8,557,971 of 494,032,768 weights had changed, because low-precision (BF16) rounding discards small updates. With full precision, accuracy stayed at 11/48.
\item Experiment 9 (448 arithmetic questions): the reward increased, but held-out accuracy decreased from 42/108 to 21/108 (Figure~\ref{fig:rlpdiv}). Answers without a readable number increased from 17 to 69, and answers at the length limit from 15 to 36.
\item Experiment 10: an early checkpoint improved at recognizing concepts (7 to 14 of 32), not at using them. Two AI graders disagreed on 44 of 321 answers.
\item Experiment 12: all 612 numeric answers in the data were correct, but 160 of 448 rules omitted a condition (for example, $\gcd(a, n) = 1$ for a modular inverse). A constant answer solved every proof-by-contradiction item.
\item Experiment 13 (decreasing support): 0 of 18 answers were fully correct at all five checkpoints.
\end{itemize}

\begin{figure}[!htbp]
\centering
\includegraphics[width=0.75\textwidth]{rlp_divergence}
\caption{Experiment 9. (a)~The quantity that the RLP reward pays for increased. (b)~Held-out answers, $n = 108$. Error bars: 95\% Wilson score intervals.}
\label{fig:rlpdiv}
\end{figure}

\emph{Why it failed}: the reward pays for reasoning that makes the answer more probable, not for correct reasoning.
This is \emph{reward hacking}.
In Experiment~9, 17 incorrect answers received a positive advantage.
A deliberately false line of reasoning increased the reward in both inspected examples.
A \emph{candidate} reason for the accuracy decrease is that training supplied the start of the answer format, but the test did not.

\subsection{A smaller goal (Experiment 11)}
\label{sec:local}
We reduced the proof to one missing expression with the mathematics supplied (Figure~\ref{fig:exp11}), and ran GRPO with $G = 8$.
Validation accuracy increased from 0/8 to 6/8, and held-out accuracy from 0/4 to 2/4.
It worked because some groups were mixed.
The sets are small, and Lean checked only the expression: only 2 of 8 explanations had no mathematical error.

\subsection{Supervised training, then whole-proof RL (Experiments 14 to 22)}
\label{sec:sftrl}
After SFT v2, the model proved 0 of the 392 non-trivial validation statements (2 of all 420).
On 200 training statements it proved 0 in 1,600 attempts.
The most frequent first errors were an invented lemma name (582), a failed rewrite (329), and the length limit (253).
The barrier moved from syntax to library knowledge.

Experiment~20 added a common SFT stage, then alternated SFT with whole-proof GRPO in one branch and with RLP in another (Figure~\ref{fig:interleaved}).
Common SFT increased the count from 0 to 13.
The GRPO branch ended at 6, below its parent, and the RLP branch at 15.
The GRPO model wrote the single tactic \code{simp\_all} in 1,637 of 3,360 attempts; the parent did so in 62.

\centering
\includegraphics[width=0.65\textwidth]{interleaved}
\caption{Experiment 20: non-trivial validation statements with an accepted proof in 8 attempts, $n = 392$. Error bars: 95\% Wilson score intervals.}
\label{fig:interleaved}
\end{figure}

Experiment~21 used rejection-sampling fine-tuning (RFT: train on sampled proofs that Lean accepts~\cite{deepseekprover15}), then GRPO.
On DEV (64 attempts per model), no model had an accepted proof.
The first errors of the final model were proof construction (43), unknown names or types (17), syntax (3), and timeout (1).
A parser fault rejected every action in a code block, so its interactive pilot made no update.
Experiment~22 prepared PPO, but the GPU run failed before RL started.

\emph{Why it failed} (\emph{candidates}): the low acceptance rate gives few mixed groups; the GRPO model concentrated on \code{simp\_all}, which closes only easy goals.
The branches also had extra SFT stages and different data, so the comparison does not isolate RL.

\subsection{Interactive RL: the clear gain (Experiment 19)}
\label{sec:interactive}
We used Formulation B from common SFT, with REINFORCE, RLOO, $G = 4$, and at most 4 actions.
We trained only on three practice theorems that the model proved some of the time.
The selection rule, fixed before the run, required more accepted DEV attempts than the parent over two seeds and no lost DEV theorem.
The rule selected the RL model (Figure~\ref{fig:mixed}).
It proved 7 of 32 original theorems without help (parent: 4 of 32), and all 7 proofs passed a new Lean check.
An earlier run of this type lost one DEV theorem, so the rule kept its parent.
Not every theorem improved: \code{Nat.not\_even\_one} decreased from 4/4 to 2/4.

\begin{figure}[!htbp]
\centering
\includegraphics[width=0.7\textwidth]{mixed_gain}
\caption{Experiment 19: SFT parent and RL model on the same theorems and seeds. Error bars: 95\% Wilson score intervals, which treat correlated attempts as independent and so understate the uncertainty.}
\label{fig:mixed}
\end{figure}

\emph{Limits}: DEV has only 3 theorems, there is one training seed, and the 32 original theorems are from the training domain.
RL made the model more reliable on proofs that it could already find; it did not show that RL teaches new proofs.

%----------------------------------------------------------------------
\subsection{Interactive RL with a curriculum (Experiment 23)}
\label{sec:curriculum}
On 22 broader theorems, a short warm-start first increased accepted whole proofs on 16 training theorems from 0 to 13.
Then an \emph{ordered} arm (answer given, one lemma, combined steps, whole proof) and a \emph{shuffled} arm trained on the same theorems.
Neither arm improved on the parent.
On broader DEV, all three models had 0 of 64.
On easy retention, the parent had 24/48, ordered 20/48, and shuffled 21/48.
On non-trivial validation, the parent proved 3 of 392 and ordered RL 1 of 392; one of the parent's accepted statements has the empty set as an answer.
The ordered model made more valid first moves than the parent (88 against 40), but it completed no proof in its first move (Figure~\ref{fig:curriculum}).

\begin{figure}[!htbp]
\centering
\includegraphics[width=0.8\textwidth]{curriculum_outcome}
\caption{Experiment 23. (a)~First action on the same 784 validation attempts. (b)~Easy retention, $n = 48$. Error bars: 95\% Wilson score intervals.}
\label{fig:curriculum}
\end{figure}

\emph{Why it failed} (four \emph{candidates}, not yet tested):
\begin{enumerate}
\item A valid action is not progress. The model learned valid actions, not complete proofs.
\item The curriculum had gaps: the lemma stage covered 9 of 22 theorems, the combined stage 11 of 22, and the early stages contained the answer.
\item For one Lean error type, the interface lost the message and gave reward 0, while ordinary errors received a penalty. A failure with a lost message therefore scored better (186 actions).
\item The environment did not show the theorem or the remaining actions, and one error ended the attempt.
\end{enumerate}
One common explanation is not supported: most repeated-state failures occurred without \code{simp\_all}.

\paragraph{Why the environment changed.}
The first move, from Formulation A to version 1, was statistical: with a terminal reward, a group updates only if it contains both an accepted and a rejected attempt (Section~\ref{sec:zero}).
Experiments 4 to 6 produced almost no mixed groups.
Version 1 made the action small enough to produce them, and Experiment 19 gave the first gain.
The second move, from version 1 to version 2, was formal: the state was too thin, an error ended the episode, and the hidden horizon made the process non-Markov.
Experiment 23 adds an empirical reason: valid first actions rose, but no proof completed.
The report records four candidate causes; two of them are environment defects rather than learner defects: the lost diagnostic, and the missing state with the terminal error.
The third move, to version 2.1, follows the same diagnosis: keep the valid prefix, put the diagnostic in the state, and let the harness backtrack.
The fourth move, to version 2.2, came from the run records, not from a new hypothesis: the parser, the checker, batch checking, lost diagnostics, proof export, and the forbidden-command filter all failed in practice.
The design also follows published interactive provers.
DeepSeek-Prover-V1.5 truncates at the first error and puts the tactic state in a comment~\cite{deepseekprover15}.
COPRA puts the error in the state~\cite{copra}.
InternLM2.5-StepProver keeps the preceding tactics~\cite{internlm}.
AlphaProof uses a step cost~\cite{alphaproof}; the discount plays that role here, but the equivalence is an inference, not a result.
No reviewed RL prover gives the policy a backtrack action.

Within the training set, exact duplicates were removed, which leaves 192 training theorems.

\begin{itemize}
\item \textbf{Settings.} Environment version 2.2, $\gamma = 0.95$, $G = 8$, at most 6 actions, REINFORCE with the leave-one-out baseline on discounted returns, learning rate $10^{-6}$, seed 20261013 for every arm, at most 150 groups per arm.
\item \textbf{Admission.} W makes 8 attempts on each training theorem. A theorem enters training only if Lean accepts 1 to 6 of the 8 attempts, so every admitted theorem can give mixed groups. A stage with too few admitted theorems is dropped from both arms.
\item \textbf{Primary measure.} The mean fraction of the 8 attempts that Lean accepts, per held-out theorem. The primary test permutes whole families, because theorems in one family are correlated; Holm correction controls the two comparisons of each claim.
\item \textbf{Efficiency.} For each arm, the gain in proved theorems over W per million generated tokens, together with Lean calls, updates, and the share of mixed groups.
\item \textbf{Validity gates.} A against B counts as confirmatory only if both arms complete the same number of groups, with updates within 10\% and censored groups within 2. The efficiency claim also needs generated tokens within 10\%. If training acceptance does not increase during RL, a null result is uninformative. No checkpoint, setting, or theorem is chosen from evaluation results.
\item \textbf{Sample size.} In simulation, the McNemar test gave a false-positive rate of up to 0.14 against the intended 0.05; the family test stays at 0.05 or less. With the final 152 theorems, the family test detects 8 to 19 percentage points in the fraction of theorems proved, and 11 to 15 points at a baseline like the parent's. These values come from an assumed model, not from data.
\item \textbf{Compute.} One L4 GPU for 12 hours, with a reservation of USD 37.01 and one attempt. A CPU fallback runs as a labelled deviation if the attempt fails.
\item \textbf{Demo.} \code{demo\_coprime} and one held-out theorem per level (a common divisor divides the gcd; odd $m$ and $n$ give an even $mn + 1$; $ab$ or $a + b$ is even), run on A if A proves at least as many held-out theorems as W, otherwise on W. Six earlier demo theorems matched statements in the training or SFT data and were withdrawn.
\end{itemize}

\subsection{Environment and learner of these runs}
\label{sec:oct19-setup}

Every run in this section uses environment version~2.2 (Section~\ref{sec:next}).
Table~\ref{tab:mdp-v22} defines it with the settings of these runs.
Figure~\ref{fig:v22-action} shows how the environment processes one action.
The settings come from the recorded run configurations. The EXP-030 record in \pth{docs/EXPERIMENTS.md} names the keys in which its configuration differs from R's.
The status names in Figure~\ref{fig:v22-action} are the action categories of Figure~\ref{fig:oct19-actions} and Section~\ref{sec:oct20-why}.

The learner uses the REINFORCE estimator of Equation~\eqref{eq:pg} with a leave-one-out baseline on discounted returns.
The loss of action $t$ in attempt $i$ is $-A_{i,t} \log \pi_\theta(a_{i,t} \mid s_{i,t}) / G$, and the gradient norm is clipped at 1.0.
For attempt $i$ of a group of $G$ attempts, the advantage of action $t$ is
\begin{equation}
A_{i,t} = \sum_{k \ge t} \gamma^{k} r_{i,k} - \frac{1}{G-1}\sum_{j \ne i}\,\sum_{k \ge 0} \gamma^{k} r_{j,k},
\label{eq:v22-adv}
\end{equation}
where $r_{i,k}$ is the reward after action $k$ of attempt $i$.
The reward comes only at the end, so every action of an attempt gets the same advantage.
If all $G$ returns of a group are equal, every advantage is 0, and the group gives no update (Section~\ref{sec:zero}).
With $\gamma < 1$, a group in which Lean accepts every attempt can still update, because proofs that close at different actions have different returns.

\subsection{No arm shows a detected held-out gain over S}
\label{sec:oct19-heldout}

In E0, S proves 1 of 163 selection theorems and accepts 1 of 326 attempts (Figure~\ref{fig:oct19-heldout}a).
E0 assesses 163 of the 164 theorems.
On group 143, a root automation probe hit the 20\,s Lean timeout, and the running code censored the whole group.
A timeout is a failed automation outcome, not an infrastructure fault; later runs record it and continue.
Comparisons with E0 therefore pair 163 theorems.
E2 loses the same group to the same defect.

E2 proves 1 of 163 theorems, E3 1 of 164, E5 0 of 164, R (E7) 1 of 164 and \code{RL\_filtered} (E6) 2 of 164.
No arm meets the promotion rule, and no paired interval excludes 0.
The largest gain is E6 against E0: $+0.92$ points, with a bootstrap 95\% interval of $[-0.61, +3.07]$.
E3 against its control E5 gains $+0.30$ points, with an interval of $[0.00, +0.91]$.
E0, E2, E3 and E7 each prove 1 theorem.
E2 and E3 prove the same theorem, and E0 and E7 each prove a different one.
This pattern fits sampling noise at the floor.

\paragraph{Capability probe.}
The probe asks whether S's near-zero acceptance comes from S or from the difficulty of the selection set.
It uses Kimina-Prover-Distill-0.6B, which its model card describes as a distillation of Kimina-Prover-72B~\cite{kimina}.
The probe uses the model card's sampling settings and checks each proof through the same verifier path as S.
In draw~1, Kimina proves 47 of 164 theorems within 8 attempts.
In draw~2, which changes only the batching, it proves 40 of 164.
An exact McNemar test on the 25 theorems proved in only one draw gives $p = 0.23$.

\emph{Limits}: the probe is not an arm matched to S.
Kimina generates whole proofs with long reasoning, not S's action format.
In draw~1, Kimina generates 6,444 tokens per attempt on average, with a limit of 8,096.
In E0, S generates about 574 tokens per attempt.
Kimina's 8 attempts therefore use far more generated tokens than S's 2 attempts.
In draw~1, 853 of 1,312 attempts reach the token limit without a closed proof and count as failures.
The pinned Lean and mathlib are probably older than Kimina's training environment, so some lemma names may not exist.
The selection theorems have no informal problem text, so the problem field of Kimina's prompt is empty.
These three effects bias Kimina's score down.
A public prover may have trained on these statements, and this unknown exposure could bias the score up.

Figure~\ref{fig:oct19-heldout}a shows Kimina's unbiased pass@2 estimates from 8 attempts per theorem.
The estimate is 11.35\% in draw~1 and 11.67\% in draw~2.
S proves 0.61\% of its 163 theorems within 2 attempts.
The panel compares models at an equal number of attempts, not at equal generated tokens.
A 0.6B prover with whole-proof generation and a larger generation budget therefore proves many of these theorems.
The probe does not separate S's model and training data from its action format and generation budget.

Kimina's proved fraction falls with reference-proof length in both draws (Figure~\ref{fig:oct19-heldout}b).
For references of at most 20 lines, it proves 28 of 62 theorems in draw~1 and 20 of 62 in draw~2.
For 21 to 40 lines, it proves 13 of 42 and 12 of 42.
For more than 40 lines, it proves 6 of 60 and 8 of 60.
Reference length describes one recorded proof; it is not a measured minimum difficulty.

\subsection{Why the TRAIN gain does not reach held-out theorems}
\label{sec:oct20-why}

RL raises acceptance on the theorems that it trains on (Sections~\ref{sec:oct19-rl-filtered} and~\ref{sec:oct19-curriculum}).
No arm shows a detected held-out gain (Section~\ref{sec:oct19-heldout}).
On 20 October, Manas asked whether this comes from the RL update or from the reward.
This subsection answers from the saved records of the runs above, with no new Lean or model run.
We consider five candidate causes: the update, the reward, the starting policy S, the held-out measurement, and the change in the policy's actions.
Every result here is exploratory and a postdiction, and none is a registered metric.
The EXP-028 entry of 20 October in \pth{docs/EXPERIMENTS.md} lists the scripts and their outputs.

\paragraph{Design.}
A \emph{visit} is one group of 4 attempts on one TRAIN theorem.
R and C visit each of the 506 TRAIN theorems twice, and \code{RL\_filtered} visits each of its 62 theorems 16 or 17 times.
The \emph{S reference} of a theorem is the number of S's 4 attempts in \code{pass\_rates} that Lean accepts.
For theorem $\tau$ and visit $v$, let $a^{(v)}_\tau$ be the arm's accepted attempts, $s_\tau$ the S reference, and $d_\tau = a^{(v)}_\tau - s_\tau$.
The test is an exact two-sided paired sign-flip test on $\sum_\tau d_\tau$.
We split the theorems by whether the arm's first visit has at least one accepted attempt.
If the policy equalled S, the second visit and the S reference would be exchangeable given the theorem, so selecting on the first visit would not bias their difference.
The split does not isolate the update from each theorem's own first visit, because the policy also changes through training on other theorems.

\paragraph{Acceptance rises where the reward is nonzero.}
Figure~\ref{fig:oct20-signal} shows the split.
On the 72 theorems where C's first visit has a proof, C's second visit accepts 95 of 288 attempts, against 54 for S ($p = 0.011$; 0.087 after a Bonferroni factor of 8).
On the 46 such theorems for R, R's second visit accepts 55 of 184 attempts, against 42 for S ($p = 0.199$).
\code{RL\_filtered} trains only on theorems that S proves in 1 to 3 of 4 attempts.
Its mean acceptance per theorem rises from 0.306 at the first visit to 0.597 at the last (Section~\ref{sec:oct19-rl-filtered}).
At the last visit, 31 of its 62 theorems have 4 of 4 accepted attempts, and 23 still have 0.
C's first visits already beat S over all 506 theorems (130 against 84 accepted attempts), so part of C's second-visit excess can come from training on earlier theorems.
The rise of \code{RL\_filtered} within its 62 theorems is the cleaner evidence.

\paragraph{The reward is rarely nonzero.}
S has no accepted attempt on 443 of the 506 TRAIN theorems.
R's first visit has a proof on 46 of the 506 theorems, and C's has one on 72.
On the other 460 theorems, R's second visit accepts 28 of 1,840 attempts, against 42 for S ($p = 0.136$).
On the other 434 theorems, C's second visit accepts 30 of 1,736 attempts, the same count as S ($p = 1.0$).
A group with no proof gives every attempt an advantage of 0 (Section~\ref{sec:zero}), so the first visit to these theorems gives no update.

\paragraph{S applies fewer tactics on held-out theorems.}
S applies at least one tactic in 105 of 326 held-out attempts (E0).
On TRAIN, it applies one in 1,199 of 2,024 attempts (Figure~\ref{fig:oct20-why}a).
By action, the counts are 156 of 1,953 held-out actions and 2,106 of 11,890 TRAIN actions.
The TRAIN theorems also carry SFT exposure.
Of the 506 TRAIN theorems, 486 have at least one SFT example from their own reference proof, and so do 59 of the 62 \code{RL\_filtered} theorems.
No SFT example comes from a selection-set statement.
On the selection set, 161 of S's 326 first actions start with \code{have} and have more than one line.
Lean rejects 147 of them at the first tactic.

\paragraph{RL concentrates on one action template.}
Of \code{RL\_filtered}'s 2,082 accepted training attempts, 1,627 close the proof with the first action (Figure~\ref{fig:oct20-why}c).
S's 84 accepted TRAIN attempts close at every action from 1 to 6.
Of the 1,627 closing first actions, 2 are a single fixed tactic without arguments.
The 12 most frequent closing texts all start with \code{simp\_all} and a lemma list, and they cover 1,076 of the 1,627.
The most frequent text, \code{simp\_all [Int.ModEq, Int.emod\_eq\_emod\_iff\_emod\_sub\_eq\_zero]}, closes 451 attempts.
In the last quarter of training, 40 theorems have a proof; 14 of them have one distinct proof text, and 10 have two.
On the selection set, 326 of \code{RL\_filtered}'s 328 first actions start with \code{simp\_all} and a lemma list.
Of these 326, Lean rejects 224 at the first tactic, 94 apply some tactics and then fail, 4 close the proof, and 4 are format errors.
The learner has no KL, entropy or reference-model term that would keep the policy near S or keep its actions varied.

\paragraph{The action limits act on R and S.}
Figure~\ref{fig:oct20-why}b splits the selection-set format errors by cause.
Of R's 1,288 format errors, 1,257 have more than 4 tactics, so the environment refuses them before Lean runs them.
Of S's 373 format errors, 320 reach the 192-token limit.
\code{RL\_filtered} makes 18 format errors.
On TRAIN, 893 of S's 1,416 format errors reach the token limit, and 465 more have more than 4 tactics.

\paragraph{The held-out test cannot detect the measured gain.}
We compute the power of the exact two-sided sign test at $\alpha = 0.05$ on theorems that one arm proves and the other does not.
The computation uses two dependence assumptions: in the nested case, the arm proves every theorem that S proves; in the independent case, the two outcomes are independent.
Negative dependence, where the arms prove disjoint theorems, is not computed, and it can give a lower power.
At the observed rates (S 1 of 163, \code{RL\_filtered} 2 of 164) and 164 theorems, the power is 0.001 (nested) to 0.006 (independent).
A grid search (every 10 theorems below 2,000, every 250 above) finds that the same gain needs 1,310 (nested) to 4,250 (independent) theorems for a power of 0.8.
At the registered 5-point bar, 164 theorems give a power of 0.693 to 0.833.
These values are for the sign test, not for the registered bootstrap rule.

\paragraph{Interpretation.}
The records show no sign of a fault in the update.
On the 62 \code{RL\_filtered} theorems, which all have a nonzero S acceptance rate, acceptance rises, and the rise is not regression to the mean.
The reward is Lean-verified, and it is rarely nonzero: S proves 63 of the 506 TRAIN theorems in 4 attempts.
On held-out theorems, S applies a tactic in fewer attempts than on TRAIN.
RL reinforces \code{simp\_all} actions with a lemma list. On the selection set, 326 of \code{RL\_filtered}'s 328 first actions start this way, and Lean rejects 224 of them at the first tactic.
The missing held-out gain is therefore consistent with a rare reward under a weak starting policy and with narrow reinforcement, more than with a fault of the update.
No run varies the reward, the starting policy, a KL or entropy term, or the action limits, so this attribution is not tested.

\emph{Alternative explanations}, not controlled:
\begin{itemize}
\item Theorems with a first-visit proof are easier. On R's split, S accepts 42 of 184 attempts on them and 42 of 1,840 on the others. A general drift toward short actions could help easy theorems without a theorem-specific update.
\item S's TRAIN advantage can come from SFT exposure, from the exclusion of theorems that one fixed tactic proves from the selection set, or from difficulty. No count separates them.
\item The \code{simp\_all} concentration changes how \code{RL\_filtered} fails. S does not show it and also proves 1 of 163 held-out theorems, so it is not the only cause.
\end{itemize}

\emph{Limits}: each arm is one training run.
The visit comparisons use 8 sign-flip tests, 4 per arm.
Under a Bonferroni factor of 8, C's first-visit gain over S stays below 0.05 (0.015), and C's split result does not (0.087).

\subsection{What the results show}
\label{sec:oct19-summary}

Measured contrasts:
\begin{itemize}
\item \code{RL\_filtered} raises acceptance on its 62 trained theorems, from a mean of 0.306 at the first visit to 0.597 at the last ($p < 0.001$).
\item C accepts more TRAIN attempts than R, 255 against 164 of 4,048 ($p = 0.0002$), in one training run per arm.
\item C's first epoch accepts more attempts than S on the same theorems ($p = 0.0019$).
\item R shows no detected rise on TRAIN.
\item No arm shows a detected held-out gain: no paired interval on the selection set excludes 0.
\item B, S, R and C each prove 0 of 8 DEV theorems.
\item RL shortens the actions. R also makes more format errors, and C concentrates on three automation tactics. These action results are exploratory.
\item Where an arm's first visit to a TRAIN theorem has no proof, the second visit shows no detected gain over S on that theorem, for R or for C. Where it has one, C's second visit gains over S ($p = 0.011$; 0.087 after a Bonferroni factor of 8). This split is exploratory (Section~\ref{sec:oct20-why}).
\item \code{RL\_filtered} starts 326 of its 328 held-out attempts with \code{simp\_all} and a lemma list. This count is exploratory.
\end{itemize}

Hypotheses, not tested:
\begin{itemize}
\item RL sharpens behaviour that S already has, rather than adding new proofs. \code{RL\_filtered} trains only on theorems that S proves at least once in 4 attempts, so its training gain cannot show new proofs. Yue et al.\ report that RL with verifiable rewards raises pass@$k$ at small $k$ but lowers it at large $k$, relative to the base model~\cite{yue2025}. This study does not measure pass@$k$ at large $k$.
\item The training rise reflects recall of proofs seen in SFT. S's SFT examples come from reference proofs of TRAIN statements, including 59 of the 62 \code{RL\_filtered} theorems, and no run separates recall from new skill.
\end{itemize}

\paragraph{Measurement floor.}
S proves 1 of 163 selection theorems and 0 of 8 DEV theorems.
The promotion rule needs a paired gain of at least 5 points, so a smaller held-out gain cannot pass it.
At the observed rates and 164 theorems, an exact sign test has a power of 0.001 to 0.006 (Section~\ref{sec:oct20-why}).
No detected gain does not show that RL gives no transfer.

\subsection{How to read this section}
\label{sec:oct21-read}

\begin{itemize}
\item Every result is exploratory and a postdiction. None is a registered metric.
\item Each arm is one training run with one seed. Section~\ref{sec:oct21-sure} shows that seed noise on the selection set is not small.
\item A \emph{valid step} is an action in which Lean applies at least one tactic. A \emph{valid attempt} is an attempt with at least one valid step. A valid step is partial progress. It is not a proof.
\item A \emph{visit} is one group of 4 attempts on one TRAIN theorem (Section~\ref{sec:oct20-why}). A \emph{decile} or \emph{quarter} is one tenth or one quarter of a run's 1,012 groups, in training order.
\item On the selection set, E0 is S, E5 is S with SFT seed 2, E6 is \code{RL\_filtered} and E7 is R (Table~\ref{tab:oct19-runs}).
\item An \emph{unknown-name error} is a Lean error that reports an unknown identifier or constant. Section~\ref{sec:oct21-harms} counts how many of these names are invented lemma names.
\item The \emph{template} is a first action that starts with \code{simp\_all} and a lemma list (Section~\ref{sec:oct20-why}).
\end{itemize}

Section~\ref{sec:oct21-sure} states which tests survive a correction for multiple tests.
It uses two families from \pth{out/p8_findings.json}.

Results from the later scripts \pth{p9_*}, \pth{p10_*}, \pth{p11_regressions} and \pth{p12_positives} are outside both families.

\subsection{What went wrong}
\label{sec:oct21-harms}

\paragraph{The learning signal is rare.}
A group gives a learning signal only if its 4 attempts get different returns.
Of 1,012 groups, R has 81 mixed groups and 920 groups in which all 4 attempts fail.
C has 103 mixed groups and 886 all-fail groups.
\code{RL\_filtered} has 207 mixed groups and 398 all-fail groups.
Groups with a nonzero advantage are 91 for R, 122 for C and 319 for \code{RL\_filtered} (\pth{p6_signal}, \code{A.*.total}).
In all three runs, the last decile has fewer such groups than the first: R 11 against 6, C 25 against 0, and \code{RL\_filtered} 61 against 21 (Figure~\ref{fig:oct21-signal}). The fall is not monotone, and it has no test.
This rare signal is consistent with the missing held-out gain. No run changes the reward or the start model, so this cause is not tested.

\item The template's mean share of first actions on these theorems rises from 0.724 in visits 1 to 8 to 0.991 in visits 9 to 16.

This pattern is consistent with the template pushing out the \code{have} and \code{interval\_cases} proofs, but no test isolates that.

\paragraph{\code{RL\_filtered} and C use Lean's error messages less.}
In \code{RL\_filtered}, the next action applies a tactic after an error in 662 of 3,260 cases in quarter~1, and in 181 of 2,120 in quarter~4 (\pth{p7_feedback}).

\paragraph{The dense reward of EXP-030 gives penalized actions a positive weight.}
EXP-030 did not run (Section~\ref{sec:oct20-not-run}).
A re-scoring of the recorded actions under its reward (Table~\ref{tab:dense-reward}) finds a design flaw.
The baseline counts all actions of the other attempts, but the reward-to-go of a late action drops the early penalties of its own attempt.
A late penalised action can therefore get a positive weight.
Of R's 22,962 penalised actions, 19,750 get a positive weight. For \code{RL\_filtered}, it is 8,306 of 11,656 (Figure~\ref{fig:oct21-dense}; \pth{p9_counterfactual}).
The script reproduces the recorded advantages with a maximum absolute difference of 0.0.
This is an off-policy re-scoring. It gives the direction of the first update only, not the result of a dense-reward run.
The records do not show that this finding caused the stop of EXP-030.

\subsection{Open questions and the test for each}
\label{sec:oct21-open}

No new run is planned. Each item names the test that would answer it.
\begin{enumerate}
\item Does a KL or entropy term stop the template collapse? Test: rerun \code{RL\_filtered} from S with a KL term to S, with the same theorems, budget and seed. Compare the template share and the late-half coverage.
\item Is the rare reward the main cause of the missing held-out gain? Test: start RL from a model that proves more TRAIN theorems, or train on theorems that S proves at a higher rate. Measure proved held-out theorems on a larger set.
\item Would relaxed action limits change what RL reinforces? Test: rerun R under 12 actions, 8 tactics and 384 tokens. Compare format errors and the closing action.
\item Did the template push out the proofs of the 11 lost theorems? Test: in a KL run, check whether these 11 theorems keep their early proofs.
\item Are the 16 TRAIN theorems that only S proves forgetting or sampling noise? Test: sample S and R 32 times each on these 16 theorems and compare the per-theorem pass rates.
\item Would retrieval of real lemma names lower the unknown-name errors after RL? Test: run E3-style retrieval on \code{RL\_filtered} and compare against \code{RL\_filtered} without retrieval.
\item Is there a held-out gain too small to detect? Test: evaluate S and \code{RL\_filtered} on a held-out set large enough for the observed rates (Section~\ref{sec:oct20-why} gives the power).
\item Does a corrected dense reward help? Test: first make the baseline count the same actions as the reward-to-go. Then re-score the recorded actions as in \pth{p9_counterfactual} before any run.
\end{enumerate}

\section{Follow-up designs that did not run}
\label{sec:oct20-not-run}

Two follow-up designs were registered on 19 and 20 October and prepared up to a dry run.
On 20 October, Manas stopped all experiments before any launch.
Neither design ran, so neither has a result or a GPU cost.
This section records their motivation and setup, because they state the open questions.
Their programs, configurations and dry-run quotes are in the EXP-029 and EXP-030 records of \pth{docs/EXPERIMENTS.md}.

\paragraph{EXP-029: more attempts, screened strata and the action limits.}
Three observations motivate EXP-029:
\begin{itemize}
\item Two attempts per theorem put every arm at the measurement floor (Section~\ref{sec:oct19-summary}).
\item The data audit of 19 October found three unchecked risks in the selection set. At least 5 of the 22 statements with quantified hypotheses that were read by hand have contradictory premises; Lean has not checked this. No screen tried short automation chains. The near-duplicate screen compares text only, so it does not flag theorems close to TRAIN proofs.
\item The selection set has already been used to choose arms, so any further result on it is exploratory.
\end{itemize}
EXP-029 evaluates S, C, R and \code{RL\_filtered} with 8 attempts per theorem on the 164 selection theorems.
Three screens split the theorems into four strata: vacuous hypotheses, automation chains, near TRAIN, and ``other''.
The ``other'' stratum is the headline.
EXP-029 also evaluates S and \code{RL\_filtered} with 8 attempts on the 62 \code{RL\_filtered} theorems.
The paired comparisons, the bootstrap and the 5-point promotion rule are those of EXP-028.

The amendment of 20 October fits the program on one L4 GPU within about USD 50.
Its dry-run quote is USD 49.51 for 28 hours, against USD 118.75 for the first program on one L40S.
It adds an exploratory comparison on the 62 theorems: S with 12 actions, 384 action tokens and 8 tactics per action, against S at the registered limits.
The limits recount of 20 October on TRAIN (\code{pass\_rates}) motivates it:
\begin{itemize}
\item 1,935 of S's 2,024 attempts use all 6 actions without a proof.
\item S's 84 proofs close at every action from 1 to 6 (Figure~\ref{fig:oct20-why}c).
\item The token and tactic limits cause 1,358 of S's 1,416 format errors.
\item At $\gamma = 0.95$, a proof closed by the last action earns 0.774 with 6 actions and 0.569 with 12.
\end{itemize}
The relaxed configuration also changes the instruction from ``up to 4 tactics'' to ``up to 8 tactics''.
The comparison therefore measures the new limits and the new wording together.

\paragraph{EXP-030: a dense per-action reward.}
Most first visits in R have no proof, and a group with no proof gives no update (Section~\ref{sec:oct20-why}).
Manas proposed a dense reward.
EXP-030 asks whether per-action penalties for Lean errors make REINFORCE close more TRAIN proofs than the terminal proof reward alone.
R\_dense starts from the same S and uses R's seed and the first 506 groups of R's frozen task order, which cover 377 distinct TRAIN theorems.
Its configuration differs from R's only in the reward mode, the run budgets and the run identifiers.
Table~\ref{tab:dense-reward} gives the reward.
The control is R's existing record of the same 506 groups, in which R closes 87 of 2,024 attempts.
The test is an exact two-sided sign-flip test on the per-group difference in accepted attempts, with groups paired by position.
R\_dense passes only if it closes more proofs than R with $p < 0.05$.
A higher return or fewer errors without more proofs does not pass.
A gaming audit compares the shares of valid actions and of no-progress actions between the arms.
R trained on an L40S, and R\_dense would train on an L4, so their sampled attempts would differ even with the same seed.

\centering
\small
\caption{The per-action reward of EXP-030 (\code{error\_feedback\_v1} in environment version 2). A partial action is scored by the failure that stopped it. An action whose next prompt exceeds the limit ends the attempt and keeps the reward of its outcome. The discount stays $\gamma = 0.95$.}
\label{tab:dense-reward}
\begin{tabularx}{\textwidth}{@{}YP{1.6cm}P{2.4cm}@{}}
\toprule
Event after an action & Reward & Label \\
\midrule

The registration of \code{error\_feedback\_v1} on 11 October gave 0 to unchanged goals, repeated states and unclassified rejections.
EXP-030 gives them $-0.1$.
Errors do not end a version~2 attempt, so a reward of 0 would let a policy avoid every penalty by repeating an action that changes nothing.
The penalties are heuristic: they score Lean errors, not proofs, so a lower error rate does not show more proof skill.
\code{RL\_filtered} makes 18 format errors in 1,948 held-out actions and proves 2 of 164 theorems (Section~\ref{sec:oct20-why}), so fewer format errors alone did not give held-out proofs.
The dense reward also penalizes Lean rejections, which are 1,636 of \code{RL\_filtered}'s 1,948 held-out actions.
No record shows what that penalty would change; this is an inference, not a result of EXP-030.

\section{Limitations}
\begin{itemize}
\item The evaluation sets are small (3 DEV theorems in Experiment~19; 4 to 8 items in Experiment~11), and every run used one seed.
\item Several sets were reused across experiments, so they now act as development sets.
\item We do not know how much Lean or mathlib the model saw in pretraining.
\item AI reviewers graded the natural-language answers in Experiments 9, 10, 11, and 13.
\item The sample-size values come from simulations with assumed parameters.
\item The numbers come from recorded run outputs; we did not repeat experiments for this report.
\item The EXP-028 selection set and the 8 DEV theorems sit near the measurement floor: S proves 1 of 163 selection theorems and 0 of 8 DEV theorems. The promotion rule needs a paired gain of at least 5 points, so a smaller held-out gain cannot pass it.
\item Section~\ref{sec:oct20-why} is a postdiction from one training run per arm. No run tests its account of the missing held-out gain.
\end{itemize}
